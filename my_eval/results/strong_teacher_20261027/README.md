## 本地接续顺序

解释器固定为`D:\conda\envs\minimind\python.exe`。脚本位于`my_eval/scripts`。

1. `test_strong_teacher.py`与`check_strong_teacher_behavior.py`检查隔离、摘要、超时控制和判分。
2. `curate_strong_teacher.py queue`合并两位老师的待审队列。填写`teacher_content_reviews.json`，每个裁决有0/1/2分及理由，只允许2分示范进入训练。写作需真正完成用户要发送的消息；解释应准确、简短，不把推测当事实。
3. `curate_strong_teacher.py build`在两位老师均完成1000条、审查全部完成且共同合格样本数量达标后，固定两组训练数据。
4. `train_strong_teacher.py weak trial`小试跑。确认显存和遮罩；然后分别执行两组`train`，每组从精确v4重新开始，训练2轮，保留所有候选。
5. `eval_strong_teacher.py dev --model <权重名>`跑v4及两组各轮候选；`review_strong_teacher.py dev`生成内容和数学待审队列。完成审查后执行`analyse_strong_teacher.py select`，只按开发集选版本。
6. 固定正式锁之后运行三组`eval_strong_teacher.py final --model <权重名>`。完成正式审查和`analyse_strong_teacher.py final`，再做独立统计复核与导出验证。
7. 新模型相对v4通过改进和保留验收才可发布；“比v4改善”和“7B老师优于1.5B老师”是两个不同结论，必须分别报告。

旧v4及此前全部实验文件保持不变。`STATUS.json`记录实际进展，本文件中的步骤不代表它们已执行。
