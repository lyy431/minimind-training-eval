## 2. 模型结构（来自 `model/model_minimind.py`）

- **稠密**：hidden 768，8 层，8 个 q 头 / 4 个 kv 头，head_dim 96，FFN 2432，词表 6400，rope_theta 1e6，词嵌入与输出层共享。共 63.91M 参数，fp32 权重文件约 137MB。
- **MoE**：每层 FFN 换成 4 个专家，top-1 路由，norm_topk_prob=True。前向时专家权重恒为 1.0，梯度靠直通估计（straight-through）传回 router；aux loss 系数 5e-4。共 198.42M 参数，激活 63.94M，权重文件 407MB。
- **可转 HF 格式**：结构与 Qwen3 / Qwen3-MoE 对齐，`scripts/convert_model.py` 可以互转。导出时 strict 加载能通过，logits 一致（最大差约 0.003，即 fp16 舍入）。
- **对话模板**：带 `<think>...</think>`；`open_thinking=True` 时开启思考，否则插入空的思考块。工具调用格式为 `<tool_call>{"name":..,"arguments":{..}}</tool_call>`，工具结果放在 user 轮里的 `<tool_response>` 中。
- **LoRA**（`model/model_lora.py`）：rank 16，只挂在 in==out 的 Linear 上（即 q_proj 和 o_proj），共 0.39M 参数。

## 5. 评测协议

| 评测 | 脚本 | 设置 | 判定 |
|---|---|---|---|
| 数学工具调用 | `eval_agent_math.py` → `compare_agent.py` | eval200 × 2 次采样；种子 `10000·题号 + 次数`；复用 `train_agent.rollout_single`（温度 0.8）；关闭思考；每轮 384 token；最多 3 轮；真实执行模拟工具 | 最终答案包含全部标准答案数字才算"全对"（`validate_gt_in_text`）；逐题配对，报告均值 ± 1 SE 和好/差题数 |
| 聊天质量 | `score_rm.py` | 30 个留出 rlaif 问题 × 3 次；开启思考；温度 0.8；512 token | GRPO 同款奖励 = 奖励模型分 + 长度项 + 思考长度项 + `</think>` 项 − 重复惩罚；分别报告总分和奖励模型分，按题配对 |
| 通用语言能力 | `heldout_loss.py` | dpo_eval300 的 chosen 回答，套对话模板，最长 768 token，只算回答部分 | 每 token 的 loss，按段落配对 |
| DPO 偏好 | `dpo_pref_eval.py` | dpo_eval300 | chosen 的隐式奖励是否更高（beta 0.15） |
| 身份 | `score_lora.py` | 7 个身份问题 × 3 次 + 10 个无关问题 × 2 次；温度 0.85，top_p 0.95，80 token | 回答里有没有出现 "Yuyang"；无关问题里出现自我介绍算"泄漏" |

**换工具列表的影响**（同样的 200 × 2）：
- bb_rl 用 demo 原来的计算器定义（措辞短、带 `"type"`、只有 1 个工具）：54.5%（vs 81.8%）
- bb_rl_id 只给计算器（训练措辞）：51.7%
- bb_rl_id 给计算器 + 翻译：75.5%
- bb_rl_id 一次给 6 个工具：30.2%

**错误类型**：
- bb_rl 剩下的错误主要是把工具结果抄进最终答案时写错数字（51 个样本；算式抄错的有 22 个）。
- bb_dist 的算式抄错有 69 个，RL 主要修好的就是这一类：算式抄对率 91.2% → 97.7%。

**训练过程**（bb_rl）：奖励从 2.76 涨到 2.84（上限 3.0），约 22% 的步全组满分，没有学习信号。替身奖励模型被调用 0 次。

- **身份**：
  - lora_yuyang：18/21，泄漏 4/20

  - 训练 loss 比稠密低约 0.025；前 20% 的步数里 MoE 落后。

  - 生成速度 39 vs 62 tok/s（逐专家循环有开销）。
  - aux loss ≈ 0.0040（理论最小值）。

- **选工具**（6 个工具，第一轮回复正确率；顺序为 full_sft / bb_rl / bb_rl_id）：
  - 数学：0 / 40 / 70%
  - 天气：22 / 78 / 33%
  - 汇率、时间、换算：全部 0%
  - 翻译：0 / 11 / 11%
  - 不该调用：94 / 72 / 61%
  - 常见错误：编造工具名（如 `calculate_current_weather`）。"只给 2 个工具"那组没有测。
- **速度**：
  - 笔记本：预训练 2.22 步/秒（约 5 小时/轮），SFT 1.32 步/秒（约 12 小时/轮）。

## 8. 决策记录（为什么这么做）

| 决策 | 原因 |
|---|---|
| 预训练和 SFT 放到云上 | 笔记本要 17 小时，云上 2.5 小时、¥6.5 |
| GRPO `max_gen_len` 512 | 1024 时 4090 显存溢出（约 22GB）：padded batch 走的是非 flash 的 fp32 注意力路径 |
| 加 `GRPO_NAME` / `AGENT_NAME` | 否则第二轮会续上第一轮的检查点 |
| 评测题用 `Random(123)` 留出，并按内容去重 | 原始数据有重复行，第一轮 agent RL 里有 1 道评测题（#108）的副本混进训练集（该题训练前后都答错，不影响结论） |
| 黑盒蒸馏只保留答对的轨迹 | 拒绝采样：只让学生学正确的示范 |
| bb_rl 本地跑，并用奖励模型替身 | 带奖励模型时显存溢出 4GB、30 秒/步、约 12.5 小时；bb_dist 每题都调用工具，奖励模型那条分支用不到，替身实际被调用 0 次 |
| 身份 LoRA 在 bb_rl 上重新训练，并混入数学样本 | full_sft 上训的 LoRA 直接合并后数学掉到 8.8%（调用次数少于算式个数的比例 0.5% → 87.8%） |
| demo 的工具定义改成训练措辞，并要求勾选 2 个工具 | 实测见 6.1 |
| demo 只监听 localhost | Streamlit 默认会暴露局域网和公网地址 |

## 9. 尚未解决 / 不确定的事
